# Development Details

Details behind the [Development](../README.md#development) section of the README: what CI checks, how releases are made, and what the tests cover.

## What CI Checks

CI (`.github/workflows/ci.yml`) runs `make setup` and `make ci` on Linux and macOS, so it runs the same checks as `make ci` on your machine: formatting, clippy with warnings as errors, and the tests. It then builds a release binary for every target that the release workflow ships.

Every cargo command runs with `--locked`, so builds and tests use the committed `Cargo.lock` as is. The Makefile passes the flag through `CARGO_FLAGS`, whose default is `--locked`.

The minimum supported Rust version (`rust-version` in `Cargo.toml`) is the `major.minor` of the Rust version pinned in `mise.toml`, which is the version CI tests with.

## Release Flow

The release workflow (**Actions → Release → Run workflow**) computes the next `yy.m.counter` version, pushes the version commit and its tag to `main`, builds every target from that tag, and publishes `safe-rm-<target>.tar.gz` archives with `SHA256SUMS`. A dry run only computes the version and shows the `Cargo.toml` and `Cargo.lock` changes.
